Download a title

One input for all downloads of a work: VLID (), link or DOI (). One selection gives a single file, several give a ZIP. blocks content marked Proxy for browser scripts; without a proxy it appears as direct links.

Options

The metadata format applies to XML, JSON and CSV. Without a proxy, JSON and CSV are taken from the catalogue data in the IIIF manifest (title, author, imprint, extent, holding institution, DOI); with a proxy, from Dublin Core or MODS.

Pages

Either work + image number(s) – the work as VLID, DOI or link, image numbers such as 30, 1-3, 30-35 or all – or just a page VLID or a link from the page view. The image number counts the digitised images from 1 and usually differs from the printed page number. All functions in this section work without a proxy.

Harvest a collection

Metadata of a set or time period via OAI-PMH. returns 10 records per request; 1000 records take about 1–2 minutes. Additional content per title increases the run time considerably.

Rule of thumb: for a table, choose oai_dc (compact) or mods (detailed) with CSV; for software, JSON; for structure, files and archiving, mets/arcmets as XML.

Additionally per title (optional)

CORS-Proxy (optional)

e-rara and e-manuscripta allow browser scripts to access full texts, entities and IIIF, but not OAI-PMH, RIS, PDF or DOI resolution. A CORS proxy forwards such requests and thereby enables harvesting, platform details and the conversion of Dublin Core/MODS into CSV/JSON.

{url} is replaced by the (encoded) e-rara or e-manuscripta address; without {url} the address is appended. Public proxies see all requests and are often throttled – for regular use, run your own proxy (instructions).
